# Quiz

## Assessment quiz (12 questions)

This quiz covers the systematic troubleshooting framework and common issue categories
taught in `01-software-support-and-troubleshooting.md`. It tests whether you can
**recognize and explain** good support practice (this is a *Has Knowledge* course), not
whether you can perform live troubleshooting. You need **80% (10/12)** to pass.

### Section 1: Clarifying the Problem (Questions 1-3)

**Question 1:** A translator messages you: "Help! Nothing is working!" According to the
framework, what is your first job before proposing any solution?
- A) Ask clarifying questions to turn the vague report into a specific, diagnosable issue
- B) Reinstall the software to rule out corruption
- C) Escalate to a vendor immediately because "nothing" is a serious symptom
- D) Restore the project from the most recent backup

**Question 2:** Which set of questions best reflects the clarifying questions the lesson
recommends asking?
- A) "Have you paid for support? Which version did you buy? Who is your administrator?"
- B) "Whose fault is this? Did you follow the instructions? Did you read the manual?"
- C) "What were you trying to do? What happened instead? When did you first notice it? Has anything changed recently? Can you show me what you're seeing?"
- D) "Can you reinstall it? Can you restart the computer? Can you try a different file?"

**Question 3:** True or False: A message like "Send/Receive isn't working" is a complete
problem description that you can act on directly.
- A) True
- B) False

### Section 2: Understanding the Context (Questions 4-5)

**Question 4:** Why does the framework treat understanding a team's context (project
structure, collaboration setup, work environment, recent changes) as its own step?
- A) Because vendors require this information before they will respond
- B) Because context replaces the need to reproduce the problem
- C) Because it helps you judge what is normal versus abnormal for that team and identify likely causes faster
- D) Because it is only relevant for brand-new projects

**Question 5:** A translator reports that a teammate's changes aren't appearing in the
shared project. Which context factor is most directly relevant to diagnosing this?
- A) How much RAM the translator's computer has
- B) The collaboration setup — how many people share the data and how they are sending/receiving it
- C) The translator's typing speed
- D) Which font the project uses

### Section 3: Reproducing the Problem (Questions 6-7)

**Question 6:** Why does the lesson recommend reproducing or directly observing the
problem (for example, by screen-sharing) rather than relying only on the translator's
verbal description?
- A) It lets you verify what is actually happening, notice details they might not mention, and test solutions in real time
- B) It creates a record for the vendor's support ticket
- C) It is required before you are allowed to escalate
- D) It guarantees the problem is the translator's fault, not the software's

**Question 7:** A translator insists "the program is broken." When you watch their screen,
you see they are clicking in the wrong place. What does this illustrate about reproducing
a problem?
- A) That verbal descriptions are always deliberately misleading
- B) That you should have escalated sooner
- C) That the software should be reinstalled
- D) That "it's not working" can turn out to be a UI/familiarity issue that direct observation reveals immediately

### Section 4: Testing Systematically and Escalating (Questions 8-10)

**Question 8:** What is the defining principle of systematic testing in the framework?
- A) Try as many fixes as fast as possible until something works
- B) Change one thing at a time, starting with the simplest common causes, and document the results
- C) Always begin with the most complex possible cause
- D) Change several settings at once to save time

**Question 9:** A file won't open. Which sequence best reflects the systematic,
one-variable-at-a-time approach the lesson describes?
- A) Reinstall the software, then reinstall the operating system, then buy a new computer
- B) Delete the file and ask the translator to start over
- C) Can they open other files? Can someone else open this file? Does it open on a different computer? Is there a backup to try?
- D) Wait a few days to see if the problem resolves itself

**Question 10:** Which of the following is a legitimate next step when a problem exceeds
what you can resolve alone?
- A) Consult someone more experienced
- B) Contact software vendor support
- C) Restore from backup or find a workaround rather than a complete fix
- D) All of the above

### Section 5: Recognizing Common Issue Categories (Questions 11-12)

**Question 11:** A translator says: "My work saved fine yesterday, but today my project
opens and a whole week of my translation is missing." Which common issue category does
this description most closely match?
- A) Missing work or data
- B) Performance problems
- C) Installation and compatibility
- D) User interface confusion

**Question 12:** A translator reports that the program has become very slow since they
started working on a large project, and that it lags when other applications are open.
Which category — and which first checks — does the lesson associate with this?
- A) Synchronization issues — check the connection and conflict reports
- B) User interface confusion — screen-share to find the missing feature
- C) Installation and compatibility — verify administrator rights and system requirements
- D) Performance problems — investigate project size, available RAM, and other running programs

---

## Answer key

1. A | 2. C | 3. B | 4. C | 5. B | 6. A | 7. D | 8. B | 9. C | 10. D | 11. A | 12. D
