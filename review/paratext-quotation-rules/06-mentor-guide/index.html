    Mentor Guide — Facilitator Notes¶

    Facilitator-facing. Read this completely before the first session. It describes how to create and distribute the practice projects, how to stage the Tamba project (TAMBA, then TAMBAB) for each phase of the course, and what text content is required. The learner-facing lessons are 01–05; the graded assessment is the quiz.

    Overview¶

    This course teaches configuration of Paratext 9.5's Quotation check using five practice projects (TAMBA, RUNDA, VELNA, MENDA, Waku), plus TAMBAB, Tamba's Phase B copy. Learners never touch a live translation project.

    The practice projects use real languages, adapted for the course. Each project holds real Scripture text and keeps its real language setting in Paratext, but carries a course name, and its quotation marks follow conventions defined by this course. The conventions tables in the lessons are the course's conventions, not a claim about how that language community writes, so don't present them to learners as facts about the language. Paratext's project lists show the real language names:

    Course project Language setting in Paratext
    TAMBA, TAMBAB Notsi (ncf)
    RUNDA English (en-US)
    VELNA Sursurunga (sgz)
    MENDA English (en-US)
    Waku Nalik (nal)

    Starting state: Paratext's defaults, not blank. TAMBA, RUNDA, VELNA, MENDA and Waku all start with Paratext 9.5's default Quotation Rules, which is what a brand-new project gets (verified: a project created in Paratext 9.5.110 saves these defaults on creation):

    Level Opening Quote Continuer at new paragraph Closing
    First level “ “ ”
    Second level ‘ ‘ ’
    Third level “ “ ”

    Continuer required at: p p/q1 b/q1. Quotation types tab: Use recommended settings, check off. These defaults are Paratext's, not the translation team's choice, and that is the teaching point: learners correct the defaults to each language's conventions rather than filling in an empty grid, and learn that a clean result at the defaults proves nothing. TAMBAB is the exception: it holds Tamba's configured settings and the five seeds.

    The Tamba project is used in two staged versions (Phase A at the defaults as TAMBA, Phase B configured and seeded as TAMBAB) across Lessons 1–4. RUNDA is a second project corrected hands-on in Lesson 2, alongside TAMBA, to practice a different character set and the apostrophe conflict. The remaining three (VELNA, MENDA, Waku) are corrected from the defaults, independently, in the scenario bank — VELNA deliberately reuses Runda's guillemet-and-apostrophe convention under a new name and project, so Scenario A tests the same skill on a project the learner has not already configured.

    Project Setup: TAMBA¶

    Step 1 — Create the project in Paratext 9.5¶

    1. In Paratext, open the main Paratext menu (☰ at the top-left of the application window) and click New project...
    2. Set the following fields:
    Field Value
    Full name Tamba New Testament
    Short name TAMBA
    Primary language The real language whose text the project uses: Notsi (ncf) for Tamba. Don't create a private-use language code (see Overview).
    Versification Original (or GNT if Original is unavailable)
    Project type Standard
    1. Click OK. Paratext creates an empty project.
    2. Leave all quotation settings at Paratext's defaults (see Overview) — learners correct them in Lessons 2–3.

    Step 2 — Add the minimum required text¶

    The project must contain text in at least the following passages. All other books and chapters can be empty or contain placeholder text.

    Book Passage Required because
    Matthew 5:1–7:29 (the Sermon on the Mount) Exercise 4.1 seed #1 — multi-paragraph speech. Jesus's First level speech opens with “ at 5:3, closes with ” in 5:12, reopens with “ at the start of 5:13 and closes again with ” in 7:27; 7:28 (narration) has no quote marks. The whole sermon must be built and correctly continuer-marked through chapter 7, since the check traces the seeded unclosed quote to 7:28
    Matthew 26:1–75 (arrest and trial) Lesson 3 check verification — heavy dialogue
    Luke 4:14–21 Exercise 4.1 seed #2 — Isaiah citation
    John 3:10–21 Exercise 4.1 seed #3 — First level continuer at the start of 3:16 (its three linked results fall at 3:10, 3:16 and 3:21)
    John 17 Exercise 1.1 — at the defaults the check reports five results here (17:1, 17:6, 17:13, 17:20, 17:24), which clear once pi is in the Continuer required at list (Exercise 2.1)
    Acts 2:22–28 (Peter's Pentecost speech) Exercise 4.1 seed #4 — Psalm 16 citation
    Romans 1:1–7 Exercise 4.1 seed #5 — apostrophe-conflict scenario

    For all other books, inserting one or two placeholder verses is sufficient. At Paratext's defaults, Exercise 1.1 (all books) gives exactly five results, all in John 17, each "Opening quote mark found without matching closing quote mark: “"; the lesson teaches that these come from the defaults, not from errors in the text. Adding pi to the default list clears all five (adding only pi/pi leaves 17:1 and 17:6). The default Second and Third level continuers produce no results in Tamba's text. Five or more books with at least a few verses each is sufficient.

    Step 3 — Apply correct Tamba quotation marks throughout¶

    All dialogue in the required passages must use the correct Tamba quotation characters:

    Level Opening Quote Continuer at new paragraph Closing
    First level (primary speech) “ U+201C “ U+201C (same as opening) ” U+201D
    Second level (embedded speech) ‘ U+2018 none — no continuer ’ U+2019
    Third level (tertiary, rare) “ U+201C none — no continuer ” U+201D

    Apostrophes: Phase A text should contain no contractions or possessives — Tamba’s course conventions do not include apostrophes in Phase A, consistent with Exercise 2.3 (which uses Runda as the apostrophe-conflict example, not Tamba). For Phase B, in the text near Romans 1:1 include a word with ’ (U+2019) as an apostrophe — the same character as Tamba’s Second level closing mark. This seeds Exercise 4.1, item 5, which Lesson 4 classifies as Neither — a quote-mark/apostrophe collision that neither a text fix nor a configuration change clears.

    Paragraph-spanning speech: Matthew 5:3–7:27 (the whole Sermon on the Mount) is the key example — not just the Beatitudes. Each verse is its own \p paragraph. Jesus's speech opens with “ (U+201C) at verse 5:3. Because Tamba's First level uses a Quote Continuer, each following paragraph also opens with “ (U+201C) — the same character, repeated to signal the speech continues from the previous paragraph. The speech closes with ” (U+201D) in 5:12 and reopens with “ at the start of 5:13, then closes again with ” in 7:27. Verse 7:28, the narrator's aside that ends the sermon, carries no quote marks. This is what the learner configures in Exercise 2.1 (Quote marks tab — the continuer character) and Exercise 3.2 (Quotation types tab — Continued quotation = Use quote marks). Lesson 3's Exercise 3.2 ("Check your work") asks the learner to confirm Matthew 5:4–7:27 is not falsely flagged, so the whole span must exist correctly marked in the Phase A baseline from Lesson 3 on. Exercise 4.1 seed #1 also depends on both closing marks (in 5:12 and in 7:27) being present in Phase A, since Phase B deletes both.

    SME verification — confirmed: a Paratext 9.5 run on a built TAMBA project confirmed the Quotation types "Continued quotation" setting does govern whether Paratext expects a configured continuer character at a paragraph break, independent of the Second and Third level settings (which have no continuer in Tamba). It also surfaced two behaviors the original design hadn't accounted for, both now reflected in the Lesson 4 Seeding table and Exercise 4.1 below: (1) an unclosed First level quotation is reported at its opening verse with wording that traces forward to wherever the next real closing mark happens to fall, rather than a fixed nearby verse; (2) a single corrupted mark — in seed #3, the First level continuer at a paragraph break — can cascade into multiple linked results on either side of the break rather than one isolated result. Re-verify both if the seeded text is rebuilt from scratch, since exact locations depend on the specific project build.

    Do not enter Tamba's conventions in Quotation Rules at this stage. The project should arrive at learners with Paratext's defaults, exactly as a new project saves them.

    Step 4 — Stage two versions of the project¶

    The course requires two states of the Tamba project:

    Phase A — Lessons 1–3 (Paratext defaults) - Quote marks tab: Paratext's defaults (“ “ ” / ‘ ‘ ’ / “ “ ”, Continuer required at p p/q1 b/q1) - Quotation types tab: Use recommended settings, check off - Text: correct marks, no deliberate errors

    Make Phase A available before learners begin Lesson 1 (Step 5). Learners correct the defaults themselves during Lessons 2–3.

    Phase B — Lesson 4 (configured + seeded errors) - Quote marks tab: fully configured per the Tamba settings above (Exercise 2.1 values), Continuer required at p p/q1 m/q1 pi b/q1 - Quotation types tab: recommended defaults with three customizations, confirmed against a real Paratext 9.5 build — Quotation from another source = Quote marks are optional, Continued quotation = Use quote marks, Indirect = Never use quote marks (the Exercise 3.2 result). Self quote already defaults to Use quote marks, which matches Tamba's requirement, so it is left unchanged. - Text: same as Phase A, plus the five deliberate errors from the Lesson 4 Seeding table below

    Phase A and Phase B are two separate registered projects: TAMBA (Phase A) and TAMBAB (Phase B, full name also Tamba New Testament). Learners can't see TAMBAB until you add them to it, which you do just before Exercise 4.1 (Step 5). Keep TAMBA at Phase A at all times: if Phase B content ever reaches TAMBA, every learner who receives it for Lessons 1–3 gets the answers.

    Step 5 — Make the projects available through Send/Receive¶

    Learners use Paratext Send/Receive only to get the projects. Each learner receives each project once, then works in their own copy on their own computer and never sends. Because nobody sends, the server copy stays at its starting state: any number of learners can work at the same time without overwriting each other, and there is nothing to reset between learners.

    All six projects (TAMBA, TAMBAB, RUNDA, VELNA, MENDA, Waku) are already on the Send/Receive server at their starting state, each with its ## Course starting state (defaults) point marked in project history. Your job as mentor is to add each learner as a user (see For each learner below). You don't set the projects up yourself. The only use for a backup file is a learner who can't use Send/Receive (see When Send/Receive isn't an option below).

    The backup set. These are prebuilt and verified. Kevin keeps the master set, outside the course repository — never in the course folder, because everything in a course folder is published on the review sites. The Phase B backup contains the Lesson 2–3 answers and the configured state of every seed, so it must stay where only mentors can reach it. When a learner needs a backup, ask Kevin for the specific file.

    "Paratext defaults" below means the default Quotation Rules in the Overview table: “ “ ” / ‘ ‘ ’ / “ “ ”, Continuer required at p p/q1 b/q1, Quotation types on Use recommended settings with the check off.

    Use this table to know which file to ask for and give an offline learner, for the project and lesson they've reached:

    Nothing to restore in your own Paratext. The projects are already set up on the server and marked, so a mentor doesn't restore any backup. Don't restore a backup over a project you already have, and never Send/Receive a restored backup: it would push over the shared project that every learner receives.

    For each learner, in your own Paratext

    1. Add the learner to each project they need now. In the project's window, open ☰ > Project settings > User permissions..., then:
    2. Click Add User... and add the learner.
    3. Click Change Role... next to the learner's name and choose Administrator.
    4. Click Book Permissions... and give them all books. A new user starts with Editable Books: None, even as an Administrator, so don't skip this step. Do it before the learner receives the project.
    5. Click OK.

    The learner needs Administrator because Lesson 3 has them tick Enable the Quotation types check, and Lesson 2 and the scenarios have them change Language Settings. Those are administrator-only settings. 2. Send the changes to the server: ☰ > Send/Receive this project. This is how the learner's access reaches the server.

    The learner receives a project from the main Paratext menu (top left of the Paratext window, not a project window's ☰ menu):

    1. Paratext > Send/Receive projects...
    2. Under Send/Receive With, leave Internet server selected.
    3. The list shows every project the learner has been given access to. A project they don't have on their computer yet is counted under the New button above the list. Tick the course project(s) they need now, and click Send/Receive. Paratext downloads them.

    WARNING: Tell the learner: receive each project once. After that, never Send/Receive it, because their changes would go to every other learner. They save their work instead. The check runs on their own copy, so their work counts without sending it. If Paratext offers to Send/Receive (for example, after a permission change), they cancel it. In testing, when Book Permissions were granted, Paratext offered a Send/Receive; cancelling it was fine and the permission still worked locally.

    You add the learner by the user name their copy of Paratext is registered under (Help > Registration information...). Get that name from them before you set them up.

    When a learner finishes the course. The projects are shared by every learner, so the user list should hold only people currently taking the course. When a learner completes the course, or stops partway through, remove them from every course project you added them to (up to all six: TAMBA, RUNDA, TAMBAB, VELNA, MENDA, Waku). In your own Paratext:

    1. In each project the learner was added to, open ☰ > Project settings > User permissions..., click Remove next to their name, then OK.
    2. Send the change to the server: ☰ > Send/Receive this project. As with adding, this is how the change reaches the server.

    Removing the learner doesn't delete the copies on their own computer. They can delete those themselves with ☰ > Project > Delete project...

    Mark the starting state. Quotation Rules and Language Settings apply to the whole project, and Send/Receive carries any change to everyone who receives afterwards. If a learner sends by mistake, the marked point is how you put the server copy's text back; the settings you reset by hand (see below). You can't restore a backup over the project instead: Paratext refuses to load it ("Waku - Waku New Testament has the same ID as Waku - Waku New Testament and was not loaded."), and Send/Receive would bring the learner's changes back from the server anyway. So the starting state is marked once, as the point to go back to.

    All six projects already carry this mark (TAMBA, TAMBAB, RUNDA, VELNA, MENDA, Waku), with the comment ## Course starting state (defaults), so a mentor has nothing to do here. It is the point the If a learner sends by mistake steps below revert to.

    Only if a project is ever rebuilt (for example, from scratch, as the scenario-bank setup section describes), mark it again after the rebuild, before any learner receives it:

    1. In the project window, open ☰ > Project > Mark point in history...
    2. Type the comment ## Course starting state (defaults) and click OK. Use the same comment on every project, TAMBAB included, so every project's reset point is found the same way. The newest mark is the one to revert to.
    3. Send/Receive the project.

    TIP: Paratext adds many history entries of its own. Starting your comment with ## makes your marked point easy to spot in the list later.

    If a learner sends by mistake. This is a recovery step, not routine: the server copy only leaves its starting state if someone sends. If a learner does Send/Receive a project after working in it, you or the learner put it back to its starting state. In that project:

In Select which books to restore, click All Books, then OK. This undoes the learner's text edits (Lesson 4 fixes, scenario edits).
    2. Set the Quotation Rules back by hand. Open ☰ > Project settings > Quotation Rules and set it to that project's starting state:
    3. TAMBA, RUNDA, VELNA, MENDA, Waku: the Paratext defaults (see the table in the Overview). Quote marks “ “ ” / ‘ ‘ ’ / “ “ ”, Continuer required at p p/q1 b/q1. Quotation types tab: Use recommended settings, with the check box off. You can use Copy quote mark settings... from another project still at the defaults; it brings the Continuer required at list across too. Confirm the list reads correctly afterwards, and check the cells rather than the Example box, which may still show the old marks.
    4. TAMBAB: Tamba's configured settings (the README's Tamba table and the Phase B description in Step 4). Quote marks “ “ ” / ‘ none ’ / “ none ”, Continuer required at p p/q1 m/q1 pi b/q1. Quotation types tab: Custom settings, check box on, with the Exercise 3.2 settings. Copy quote mark settings... from a project at this state brings the list across with the marks; confirm the list reads correctly afterwards.
    5. Check Language Settings where the course has learners change them. Open ☰ > Project settings > Language Settings > Other Characters and make sure Word-medial punctuation is back to its starting state (empty) on the projects where learners add ’: RUNDA (Exercise 2.3), VELNA (Scenario A) and TAMBAB (Exercise 4.1, item 5).
    6. Click OK, then Send/Receive the project.

    WARNING: Reverting has costs. It also wipes the learner's own work since the marked point, so they redo it. And anyone who received the project between the send and the revert keeps the leaked settings.

    If a learner received the leaked settings, reverting the server copy doesn't fix their copy. After the revert, tell them to:

    1. Delete their copy: ☰ > Project > Delete project...
    2. Receive it again: Paratext > Send/Receive projects...
    3. Redo their own work in that project.

    Deleting their copy doesn't remove them from the project, so it appears in their Send/Receive list again straight away.

    Reverting doesn't remove users. That doesn't matter here, because the learner keeps working; if you also want to take them off the project, remove them yourself as in When a learner finishes the course above.

    When Send/Receive isn't an option. If a learner has no reliable internet connection, give them the matching backup file to restore on their own computer instead (Paratext menu > Advanced > Restore project from file...). Ask Kevin for the specific file (see the backup table in Step 5). Don't hand out the TAMBAB backup until they reach Lesson 4.

    Project Setup: RUNDA (Lesson 2)¶

    RUNDA is a second practice project, alongside TAMBA, used hands-on in Lesson 2 (Exercises 2.2–2.3) to practice correcting the defaults to a different character set (guillemets) and to work through the word-medial apostrophe conflict — including discovering, on a real Paratext 9.5 check, that Word-medial punctuation does not actually clear the resulting flag. It must be installed before learners start Lesson 2, not just before the scenario bank.

    Field Value
    Quotation style Guillemet outer (« / »), curly single inner (‘ / ’)
    Minimum books suggested Matthew, Luke, John (dialogue-heavy)

    Include words using ’ (U+2019) as an apostrophe somewhere in the text, so Exercise 2.3's word-medial punctuation conflict has real examples to work through — the exercise now expects learners to confirm the check keeps flagging these even after configuring Word-medial punctuation, not to reach zero results. Leave Quotation Rules at Paratext's defaults — learners correct them during Lesson 2. RUNDA is already on the Send/Receive server at this starting state; add the learner as described in Step 5 above. A prebuilt backup is available from Kevin, for a learner who can't use Send/Receive.

    Expected results (Quotations check):

    State All books Matthew What the learner should notice
    Paratext defaults (start of Exercise 2.2) 1110 — Mostly (767 of the 1110) "Closing quote [ ’ U+2019 ] found as a word medial character…": the text uses ’ as an apostrophe (in contractions and possibly a glottal stop) as well as the Second level closing mark.
