# Data Model: Searchable Resource Library

## Resource

One entry in `resources.yaml` at the repo root. This file is the library's only source of truth (FR-003, R2).

| Field | Type | Required | Rule |
|---|---|---|---|
| `title` | string | yes | Not empty. Becomes the `####` heading on the library page (R3). |
| `url` | string | yes | Starts with `http://` or `https://` (R5). Large files are linked where hosted, never committed. |
| `description` | string | yes | One line. A description of a named language's script or orthography comes from a human source (constitution VIII). Until then it is a marked placeholder. |
| `type` | enum | yes | One of `guide`, `video`, `site`, `document` (R5). |
| `competencies` | list of strings | yes | At least one entry (SC-002). Each name matches `competencies.yaml` verbatim (FR-002). |
| `language` | string | yes | The resource's interface language. Two resources on the same topic in different languages are separate entries. |

Validation:
- `check_competency_descriptors.py` checks every entry. A missing field, an unknown type, a non-http(s) url or an unknown competency name fails the build.
- An entry never points at a `modules/` file. The library holds no answer keys, mentor guides, design docs or video scripts (FR-012).

## Competency (reshaped)

Defined by `competencies.yaml`. Its descriptor in `competencies/*.md` loses its `resources:` field. The entries move to `resources.yaml` and are not copied (R2).

Relationships:
- A competency has many resources. A resource has one or more competencies.
- A competency belongs to one framework category. The library page groups resources by category, then by competency (R4).
- A competency page's Further Information section lists the resources that name it (R4). Its URL does not move (FR-011).

## Library page

Generated by `gen_site.py` from `resources.yaml`. It is text only (R8).

- One `####` heading per resource, with description, type, language and competency names under it.
- Each heading has a stable anchor. Lessons link to `/library/#<anchor>` (R7).
- The page is overwritten on every publish (FR-010). If its path ever moves, the old path is redirected in the same change (FR-011).

## Library entry point

A "Library" item in Moodle's custom menu and in the Moodle app's main menu. Both are declared in `moodle/site/settings/learner-experience.yaml` and applied by `site_config.py` (R7). It points at the library page. If the app setting does not exist on 5.2, the item becomes a route in `block_ltuse` instead.

## Link check result

Produced weekly by `scripts/check_resource_links.py` (R6). It lists each resource whose url fails a HEAD request and then a GET.

State transitions for the one GitHub issue that carries it:
- No issue and no broken links: nothing happens.
- Broken links found: the issue is opened, or updated if it is already open.
- An open issue and no broken links: the issue is closed with a comment saying all links pass.
